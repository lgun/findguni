# Findguni 플랫폼 재구축 설계

## 제품 원칙

- 메이커는 가입/로그인 후 자기 게임만 만들고 수정한다.
- 게임은 초안과 불변 발행본을 분리한다. 새로 발행해도 진행 중인 플레이는 시작 당시 버전을 사용한다.
- 플레이어는 로그인하지 않는다. 브라우저에는 무작위 기기 토큰만 `HttpOnly`, `SameSite=Lax` 쿠키로 저장하고 진행/시도/인벤토리는 서버 DB에 저장한다.
- 게임은 기본적으로 링크 공개이며, 메이커가 원할 때만 공개 탐색 목록에 노출한다.
- 모든 플레이 UI는 모바일 우선이며 키보드 조작과 터치/스와이프 조작을 함께 지원한다.

## 역할과 권한

- `MAKER`: 자신의 게임, 스테이지, 아이템, 발행본, 통계 관리
- `ADMIN`: 전체 메이커 상태, 전체 게임 공개 상태, 플랫폼 지표 관리
- `PLAYER`: 계정 없이 공개된 플레이 링크에서 시작/이어하기/재시작

소유권 검사는 URL의 ID만 신뢰하지 않고 서비스 계층에서 현재 로그인 메이커와 게임 소유자를 항상 대조한다.

## 핵심 도메인

- `UserAccount`: 이메일, 비밀번호 해시, 표시 이름, 역할, 활성 상태
- `EscapeGame`: 메이커 소유 게임 초안, slug, 테마, 커스텀 색상·아이콘, 플레이 도구 허용 설정, BGM과 attribution, 스토리 속도·비네트 설정, 난이도, 공개 범위, 발행 버전
- `GameStage`: 정렬 가능한 스토리/퍼즐 스테이지 초안. 장면 이미지·연출 효과·SFX와 attribution을 포함한다.
- `GameItem`: 열쇠·문서·사진·지도·도구·기호·증거·장치·음식·커스텀 유형의 아이템 초안. 사진, QR 단서 내용과 QR 활성 여부를 포함한다.
- `GameRelease`: 발행 시점의 게임/스테이지/아이템 JSON 스냅샷
- `PlaySession`: 익명 기기와 발행본에 연결된 진행 상태, 인벤토리, 메모, 완료 상태
- `ScannedClue`: 플레이 세션에서 인식한 발행본 아이템 QR 목록. 세션과 아이템 키 조합은 중복되지 않는다.
- `PlayAttempt`: 스테이지별 정답/오답 시도와 힌트 사용 분석 데이터

## 제작 템플릿과 테마

- 빈 게임, 10분 퀵게임, 미스터리 저택, 탐정 사건, 폐병원, 보물 사냥, 학교 미션, 박물관 탐방
- 비밀 연구소, 판타지 퀘스트, 야외 트레일, 축제 이벤트, 키즈 어드벤처, 팀 레이스
- 프리셋 테마를 고른 뒤 강조색·보조색·배경색과 게임 아이콘을 개별 변경할 수 있다.
- 아이템은 유형 10개와 32개 아이콘 프리셋을 제공하며, 임의 이모지와 사진도 사용할 수 있다.

## 퍼즐 컴포넌트

- 스토리
- 숫자 휠 자물쇠
- 숫자 키패드
- 알파벳 휠 자물쇠
- 방향 자물쇠(버튼 및 스와이프)
- 색상 순서 자물쇠
- 객관식
- 단답형

정답은 HTML로 내려보내지 않고 서버에서 유형별로 정규화해 검사한다.

## 주요 URL

- `/`, `/games`: 소개 및 공개 게임
- `/signup`, `/login`: 메이커 가입/로그인
- `/maker`: 메이커 대시보드
- `/maker/games/new`: 템플릿으로 게임 생성
- `/maker/games/{id}/edit`: 설정, 테마, 스테이지, 아이템 빌더
- `/maker/games/{id}/publish`: 새 불변 버전 발행
- `/maker/games/{id}/qr`: 플레이 링크 QR 이미지
- `/maker/games/{gameId}/items/{itemId}/qr`: 게임 아이템 단서 QR 이미지
- `/maker/audio/search`: 인증된 메이커의 Openverse BGM·SFX 검색 JSON
- `/play/{slug}`: 게임 소개와 시작/이어하기
- `/play/{slug}/stage`: 현재 진행 화면
- `/play/{slug}/scan`: 브라우저가 읽은 QR 문자열 또는 카메라 프레임 검증
- `/play/{slug}/clue/{itemKey}`: 일반 카메라 앱에서도 사용할 수 있는 아이템 단서 링크
- `/play/{slug}/notes`: 현재 익명 플레이 세션의 메모 저장
- `/platform`: 통합 관리자

## 사진과 QR 처리 원칙

- 모바일 파일 입력의 카메라 캡처를 이용해 제작 현장에서 아이템 사진을 바로 촬영할 수 있다.
- 업로드는 8MB 이하의 JPG·PNG·WEBP만 받고, 실제 이미지 디코딩과 해상도 검사를 거친 뒤 최대 1600px로 축소·재인코딩한다.
- 원본 파일명은 저장 경로에 사용하지 않고 서버가 UUID 파일명을 발급한다.
- 플레이어 QR 스캐너는 `BarcodeDetector`를 우선 사용하고, 미지원 브라우저에서는 카메라 프레임을 서버 ZXing 디코더로 전송한다.
- 스캔 결과는 현재 플레이 중인 불변 발행본에 포함되고 QR이 활성화된 아이템만 허용한다. 외부 URL은 자동으로 열지 않는다.
- 카메라 권한을 줄 수 없는 환경에서는 촬영/파일 선택 또는 일반 카메라 앱이 아이템 단서 링크를 여는 흐름을 제공한다.

## 플레이 도구

- 인벤토리는 퍼즐 보상과 QR로 발견한 아이템을 현재 익명 플레이 세션에 저장한다.
- 단서장은 인식한 QR 아이템을 중복 없이 기록해 다시 열람하게 한다.
- 메모장은 플레이어의 자유 메모를 서버 세션에 저장해 같은 기기에서 이어할 수 있게 한다.
- 메이커는 메모장, 단서장, 인앱 QR 스캐너를 게임별로 각각 허용하거나 숨길 수 있고 이 설정도 발행본에 고정된다.

## 스토리·오디오 처리 원칙

- 게임 전체 BGM은 음원 URL, 제목·저작자·라이선스·라이선스 원문·출처 원문, 음량, 반복 여부를 함께 관리한다.
- 각 스테이지는 장면 이미지, 연출 효과, SFX URL과 attribution, 음량을 별도로 관리한다. 게임의 글자 표시 속도와 비네트 설정은 모든 장면의 기본 연출이 된다.
- 직접 업로드는 MP3(`ID3` 또는 MPEG frame), OGG(`OggS`), WAV(`RIFF`/`WAVE`) magic header를 검사한다. BGM은 30MB, SFX는 8MB 이하만 받고 `/uploads/audio` 아래 UUID 파일명으로 저장한다.
- 외부 음원과 attribution URL은 HTTPS만 허용한다. `javascript:`, `data:`, `file:` 같은 실행·로컬 scheme과 임의 업로드 경로 조작은 거부한다.
- 발행 시 BGM·SFX·장면·스토리 설정과 attribution을 JSON 스냅샷에 복사한다. 이후 초안을 바꿔도 이미 시작한 세션의 연출과 라이선스 표시는 바뀌지 않는다.
- 브라우저 자동 재생 제한을 존중한다. 첫 사용자 제스처에서 오디오 재생을 복구하고, 플레이어의 BGM/SFX 선호와 현재 게임의 재생 위치만 클라이언트 저장소에 보관한다.

## Openverse 경계

- 메이커 빌더는 [Openverse API](https://api.openverse.org/)의 익명 오디오 검색을 사용해 미리듣기 URL과 제목·저작자·라이선스·원문 링크 metadata를 가져올 수 있다.
- Openverse 익명 API는 rate limit과 페이지 깊이 제한을 적용하며 초과 시 429를 반환할 수 있다. 서버는 짧은 타임아웃, 제한된 결과 수와 실패 가능한 보조 기능으로 취급한다.
- Openverse와 실제 파일을 호스팅하는 외부 제공자의 가용성은 Findguni가 통제하지 않는다. 외부 파일이 삭제·교체되면 미리듣기와 플레이가 실패할 수 있다.
- Openverse는 집계한 콘텐츠와 라이선스 상태의 정확성을 보증하지 않는다. 메이커는 [Openverse 이용 약관](https://docs.openverse.org/terms_of_service.html)과 원문 페이지에서 사용 권한을 독립적으로 확인하고, 라이선스가 요구하는 저작자·출처·라이선스 표기를 유지할 책임이 있다.

## 이번 재구축 범위

이번 구현은 다중 메이커 격리, 인증, 14개 템플릿, 테마 커스터마이징, 사진·QR 아이템 빌더, 스토리 장면과 BGM·SFX, 버전 발행, 익명 이어하기, 인벤토리·단서장·메모장, 퍼즐 인터랙션, 메이커 통계, 통합 관리자를 하나의 동작 가능한 MVP로 완성한다. 실시간 공동 편집, 결제, 커스텀 도메인, 외부 오브젝트 스토리지, 다국어는 후속 확장 경계로 둔다.
